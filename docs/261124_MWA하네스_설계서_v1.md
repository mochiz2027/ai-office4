## 2. BMAD 역할 → 층 매핑

| BMAD 단계 | 산출물 | 담당 | 층 |
|---|---|---|---|
| 1. 분석 | 아이디어 다듬기, 브리프 | 비즈니스 분석가 | 2F |
| 2. 기획 | PRD(MVP 범위·완료 조건), UX 문서 | PM, UX 디자이너 | 2F |
| 3. 솔루셔닝 | 아키텍처 결정·스타터, 티켓 트리, 개발 직전 점검 | 아키텍트, PO | 2F |
| 4. 구현 | 에픽 다듬기 → 개발 → 자동 테스트 → 리뷰 → main → 회고 | SM, 개발자, 리뷰어 | 3F·4F |

## 3. 시스템 구조

```
mwa (bin/mwa.js)          up / init / doctor / status
 └─ office/server
     ├─ server.js          HTTP + SSE(실시간), 같은 출처 요청만 허용, 127.0.0.1 바인딩
     ├─ orchestrator.js    진행기(상태 기계)
     ├─ engine.js          claude(-p, stream-json) / mock 엔진
     ├─ ledger.js          공백 장부 계산
     ├─ store.js           .mwa/state.json 영속화(재시작 시 이어서 진행)
     └─ roles.js           층·역할·기획 단계 정의
 └─ office/agents/*.md     역할별 프롬프트 + 공통 출력 계약(_contract.md)
 └─ office/web             바닐라 JS UI (외부 라이브러리 없음)
```

### 3.1 에이전트 출력 계약
모든 에이전트는 작업 후 응답 마지막에 JSON 블록을 하나 출력합니다. 진행기는 이 JSON 만 보고 다음 행동을 정합니다.

```json
{ "summary": "...", "questions": [{"q": "...", "options": ["A","B"], "recommended": 0, "why": "..."}],
  "assumptions": ["..."], "testCommand": "(아키텍트)", "epics": "(PO)", "verdict": "(점검·리뷰)" }
```

- `questions` → 자동 모드는 추천안으로 즉시 확정(기록은 남고 나중에 변경 가능), 수동 모드는 사람 차례로 대기합니다.
- `assumptions` → 공백 장부 ②칸. 대표가 "틀림"으로 표시하면 이후 모든 지시에 "틀린 가정"으로 전달됩니다.

### 3.2 빌드 루프(티켓 1건)
1. `mwa/T<n>` 브랜치 생성 → 2. 4F 개발자 구현(도구: 파일 편집 + Bash) → 3. 3F 테스트 명령 실행 → 4. 3F 리뷰어 검토(읽기 전용) → 5. 승인 시 커밋 후 main 에 `--no-ff` 병합
- 테스트 실패·리뷰 반려 시 피드백을 붙여 개발실로 되돌리며, 최대 3회 시도 후 실패하면 "사람 차례"로 올립니다(재시도/건너뛰기).

### 3.3 권한 설계
- 기획 에이전트: Read/Write/Edit/Glob/Grep
- 리뷰어: 읽기 + `git diff/status/log` 만
- 개발자: 위 + Bash 전체 — 프로젝트 폴더에서만 실행되지만 명령 제한은 없으므로 WSL 이나 전용 폴더에서 실행할 것을 권장합니다.
